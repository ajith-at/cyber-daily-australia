01 // STRATEGIC FOUNDATION & SCOPE

Executive Context and End-to-End Lifecycle Scope

END-TO-END LIFECYCLE

Enterprise adoption of Artificial Intelligence (AI) has progressed from static chat interfaces to autonomous agentic systems that plan, reason, invoke tools, and execute actions across corporate environments. Governing these systems requires embedding security assurance across all seven lifecycle stages.

STAGE 01

Code

Isolated development workspace, approved model library, and scoped tool selection.

STAGE 02

Build

Dependency verification, Artificial Intelligence Bill of Materials (AI BOM) registration, and identity binding.

STAGE 03

Test

User Acceptance Testing (UAT), pattern validation, prompt injection testing, and sandbox escape verification.

STAGE 04

Release

Change Advisory Board (CAB) sign-off, remediation verification, and formal risk acceptance.

STAGE 05

Deploy

Automated Continuous Integration and Continuous Deployment (CI/CD) promotion behind external guardrails.

STAGE 06

Operate

Enforced runtime boundaries, human approval gates, and least-privilege token exchange.

STAGE 07

Monitor

Behavioural drift detection, immutable audit telemetry, containment triggers, and reassessment loops.

Governance and Accountability CAT-01

Establishes explicit business ownership, ten-minute triage intake, formal risk acceptance thresholds, and human oversight models across every deployment.

Technical Guardrails CAT-02

Enforces deterministic identity context, network segmentation, data minimisation, and execution sandboxing outside the model and agent harness.

Assurance and Monitoring CAT-03

Validates pre-release security posture through the AI Security Assurance Process and continuously correlates runtime tool activity after go-live.

Operational Profiles Across the Seven Agent Archetypes

RUNTIME BEHAVIOUR

Knowledge & Workflow TYPES 1-2

Persistent Personal Agents retain cross-session state across user mailboxes. Specialist Business Agents execute procurement, legal, and finance workflows. Multi-Agent Systems orchestrate isolated runtimes with dedicated vaults.

07 // OPERATIONAL GOVERNANCE PROCESS

End-to-End AI Security Assurance Process Workflow

5-STAGE WORKFLOW

Stage 1: Intake & Triage Form 10 MINS

Project team submits an initial consultation request and completes a ten-minute triage questionnaire capturing project scope, autonomy, tools, data sensitivity, and network reach.

Stage 2: Triage & Pattern Match PATTERN CHECK

Security team evaluates inputs against existing approved patterns (such as a standard Copilot Studio knowledge assistant). Matching deployments follow a streamlined Pattern Assessment.

Stage 3: Risk-Based Routing ROUTING

Unmatched deployments are scored across the eight triage dimensions into Low (triage sufficient), Medium (Focused AI Security Assurance Process), or High (Full AI Security Assurance Process).

Assurance Routing Decision Matrix and Post-Implementation Loop DECISION FLOW

PATH A // MATCHED PATTERN

Pattern Assessment

Verify conformance to pre-approved architectural baseline controls.

PATH B // LOW RISK

Direct Release Gate

Initial triage validation suffices; proceeds directly to release approval.

PATH C // MEDIUM RISK

Focused Assurance

Targeted assessment covering only dimensions rated Medium or High.

PATH D // HIGH RISK

Full Assurance Process

Comprehensive 9-domain security assessment plus 6-domain red team testing.

Stage 4: Remediation and CAB Release RELEASE GATE

Project teams address all findings from the AI Security Assurance Process before entering standard release governance, CAB approval, and production deployment.

Stage 5: Material Change Reassessment CONTINUOUS LOOP

Production monitoring tracks material changes in tools, models, or permissions, automatically triggering a fresh reassessment request when the security profile shifts.

10 // FULL AI SECURITY ASSURANCE PROCESS (PART 1)

Comprehensive Security Assessment: Nine Core Domains

ASSESSMENT PILLAR

High-risk initiatives undergo the Full AI Security Assurance Process, beginning with a rigorous nine-domain architectural and operational security assessment.

01. Architecture Review DOM-01

Maps trust boundaries, end-to-end data flows, attached tools, and external platform dependencies.

02. Threat Modelling DOM-02

Identifies concrete attack paths, business logic abuse cases, and control displacement caused by agent autonomy.

03. Identity & Access DOM-03

Verifies human user, workload, and agent identities alongside downstream authorisation and token scoping.

04. Data Governance & Privacy DOM-04

Reviews data classification, input-output minimisation, privacy obligations, retention schedules, and disclosure controls.

05. Supply Chain Risk DOM-05

Evaluates foundation models, MCP connectors, third-party SaaS solutions, software packages, and hosted services.

06. Human Oversight Controls DOM-06

Validates approval gates across HITL, Human-on-the-Loop (HOTL), and Human-out-of-the-Loop (HOOTL) models with override switches.

07. Logging & Monitoring DOM-07

Confirms deterministic attribution of all actions to the specific agent, environment, and owning team with drift alerts.

08. Incident Response DOM-08

Validates compromise detection playbooks, rapid agent disablement procedures, forensic investigation, and recovery.

09. Operational Resilience DOM-09

Analyses model and tool failure modes, rollback procedures, recovery objectives, and continuity during dependency loss.

11 // FULL AI SECURITY ASSURANCE PROCESS (PART 2)

Adversarial Security Testing and Runtime Containment

RED TEAM TESTING

The second pillar of the Full AI Security Assurance Process validates runtime resilience through six adversarial security testing regimes prior to production release.

01. Adversarial Red Teaming TEST-01

Executes multi-step goal subversion exercises to test whether autonomous planning can be redirected toward unauthorised objectives.

02. Prompt Injection TEST-02

Tests resilience against direct user prompt overrides and indirect injections embedded in retrieved SharePoint files, emails, or web pages.

03. Tool Abuse Testing TEST-03

Attempts parameter manipulation, unauthorised API invocation, confused deputy privilege escalation, and unsafe tool chaining.

04. Output Validation TEST-04

Verifies that generated payloads, code snippets, and downstream API arguments are strictly sanitised and schema-validated before execution.

05. Data & Memory Abuse TEST-05

Tests defences against sensitive training or context exfiltration, cross-session data leakage, and persistent shared memory poisoning.

06. Sandbox Escape & Containment TEST-06

Probes container, micro-VM, file system, and network egress boundaries to confirm coding and task agents cannot escape runtime isolation.
