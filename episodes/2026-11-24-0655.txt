From Melbourne, this is U51 with your cyber and AI security brief for Tuesday the 24th of November, covering the 24 hours to about six this morning, Melbourne time.

Here are the headlines. Norway says attackers exploited a flaw in Microsoft's Azure API Management service to go after secrets at energy companies, and customers need to rotate credentials even though the hole is closed. CrowdStrike has agreed to buy Zscaler for almost 44 billion US dollars, outstripping Google's purchase of Wiz. Attackers are exploiting a critical flaw in an ASP.NET security library that was abandoned in 2008 and will never be patched. And India's cyber agency warns that payment fraud through organisations' own approval systems has spread beyond banks, as AI-driven attack frameworks turn up across sectors.

Our lead story is a cloud flaw with a long tail. Norway's National Security Authority, known as NSM, says an unknown actor has been actively going after access tokens, secrets and stored configuration values in Azure API Management, the Microsoft service many organisations use as the front door for their application programming interfaces. Two Norwegian energy companies were hit. Equinor, one of Europe's largest gas suppliers, says it detected an attack on some of its IT systems last Tuesday and stopped it on Friday. Oil and gas production carried on, and it has found no sign that data was stolen or altered. Electricity producer Skagerak Energi disclosed a separate incident the next day, with no effect on operations. NSM says organisations in several sectors, in Norway and abroad, are affected, and credits Equinor with spotting the problem early.

Microsoft's own advisory has not been published, but according to copies seen by The Register and The Record, Microsoft identified the issue on the 18th of November and closed the access path the following day. It says an unauthorised party could have reached secrets stored in the older Classic tiers before then, particularly where customers hadn't followed its network guidance or kept secrets directly in the service rather than in Azure Key Vault. The newer version two tiers were not affected. The exposed material includes subscription keys, identity provider client secrets and management tokens, and as one researcher pointed out, a stolen credential can often be used directly against whatever sits behind the gateway. So the fix on Microsoft's side does not end the job on yours. If you run a Classic-tier instance, assume anything stored in it is exposed: rotate every secret, key and token, move secrets into Key Vault, review access logs, and check the runtime version against the thresholds NSM has published, which are in the show notes. Don't forget the development and test instances nobody remembers creating. How widely this was exploited, and by whom, is still unclear.

Global threats.

Google's Mandiant has found attackers exploiting a critical flaw in Idunno AntiCsrf, an old open-source module that was meant to protect ASP.NET Web Forms sites against cross-site request forgery. Instead, it deserialises whatever it's handed, so a single unauthenticated web request can run code on the server with the rights of the web application. It's rated 9.3 out of ten. The project hasn't been touched since December 2008, so there is no patch coming. The advice is to rip it out, replace it with a supported protection, search your web configuration files and application folders for any reference to it, and if you find signs of exploitation, rotate the machine keys, encryption keys and database passwords stored in the configuration. It is a reminder that the software you forgot about has not forgotten about you.

A follow-up on the ConnectWise ScreenConnect technician flaw we covered last week. Research Huntress published last week shows attackers spraying it blindly: more than 688,000 requests from guest machines trying to make technicians run a file, hitting 42 ScreenConnect servers from 29 addresses between late October and mid-November. In one case a technician's workstation went from that file to a rogue remote-access client in about nine seconds. The fix sits on the technician's side, so managed service providers should make sure every technician client is on the fixed version, which is in the show notes.

Another follow-up from Saturday: N-able has disclosed a critical server-side request forgery flaw in its Mail Assure email filtering platform, found while investigating last week's breach. It could let a user with high-level access to the programming interface probe and send data to internal systems. N-able has fixed it on its own platform and restored the dashboard and its programming interfaces, but hasn't said whether this was how the attackers got in.

Security firm Rapid7 says the China-aligned group Webworm appears to be using a modified build of the open-source SoftEther VPN Bridge, rebranded and disguised as network monitoring software, to keep covert remote access inside victim networks. The attribution is held with moderate confidence. Webworm has previously targeted government agencies, IT service providers and electricity companies, so unexpected VPN bridge software on a server deserves a second look.

In breach disclosures, Austria's Foreign Ministry says a website run by an outside provider was breached in mid-November, exposing the names and official contact details of staff in Vienna and at embassies abroad. No one has been blamed, and how the attackers got in is unclear. The ministry has been targeted before: earlier this year Vienna publicly blamed Russia for an intrusion that ran for weeks in 2019 and 2020. Spain's LaLiga says an attacker extracted personal data from one of its fan-services platforms over three days in mid-November. And gift card distributor GlobeTopper's parent company told United States regulators that an October intrusion cost it about two and a half million dollars in lost revenue, plus seventy thousand dollars in gift cards the attacker redeemed and that it can't claw back. It also says the attacker took some business customers' programming interface credentials and keys, which have since been replaced.

Developers using the Node.js library binary-parser should update: a code injection flaw lets anyone who controls a parser definition run JavaScript when it's compiled. Parsing untrusted data with your own definitions is not affected.

AI security.

India's Computer Emergency Response Team, CERT-In, warns that fraud through business payment systems is no longer limited to banks and lenders. It's now hitting technology providers that support government-linked payments and platforms that handle vendor or partner payouts. Attackers altered business records and approval relationships, then pushed unauthorised transactions through otherwise legitimate systems. CERT-In hasn't said how much was lost or who is behind it. Its earlier advisories linked AI-assisted tooling to faster payment fraud at financial firms. The agency also reports agentic attack frameworks in use against enterprise, government and research targets, and recommends reviewing business applications, identities and third-party interfaces, and making sure incident response covers the misuse of trusted processes, not just malware.

Research from security firm OX Security, which is self-reported, suggests attackers are shifting how they poison tools for AI agents. In flagged servers built on the Model Context Protocol, the standard that lets agents call outside tools, prompt injection and tool poisoning turned up more often than old-fashioned malicious install code. Nearly half of the small sample of flagged agent skills told agents to send data out. Nothing in those tools has to run code: the risk comes from agent harnesses that trust whatever a tool description says and hold broad access to act on it.

On the defensive side, Google has published results for a guardrail that checks each action an agent proposes against what the user actually asked for. On a public test suite of prompt injection attacks, it says the success rate fell from almost half to under one in a hundred, at a small cost to normal tasks. Those are the vendor's own figures, but the approach is sound: an agent paying a bill should not be quietly adding a new payee.

Industry.

CrowdStrike will acquire Zscaler in an all-stock deal worth 43.9 billion US dollars, announced on Monday United States time. Zscaler shareholders get just over one CrowdStrike share for each of theirs, and Zscaler's chief executive will keep running the business and join CrowdStrike's board. The deal takes CrowdStrike from endpoints into network security and opens up about 8,000 Zscaler customers who don't yet use CrowdStrike. It also tops Google's 32 billion dollar purchase of Wiz. For customers, the practical questions are about product roadmaps and contracts, and with deals of this size, regulators will have their say before anything closes. CrowdStrike pitched the combination as a single control plane for AI and agents, which is this year's way of saying "platform".

Outlook and patch priorities.

First, Azure API Management Classic customers should rotate everything stored in their instances today and check the runtime version. Second, find and remove the Idunno AntiCsrf module from any old ASP.NET application. Third, managed service providers should confirm every ScreenConnect technician client is updated. In the United States, federal agencies face today's deadline on four exploited flaws added earlier this month, in Microsoft Office, Cisco BroadWorks, Google Chrome and an Openwave media transcoder. Over the next two days, watch for a public Microsoft advisory on the API Management flaw and any further named victims, whether N-able confirms how its attackers got in, and the first regulatory signals on CrowdStrike and Zscaler.
