The headlines. PHP, the language underneath a very large share of the world's websites, has shipped emergency fixes for two critical flaws that let an attacker with no account run code on a web server, and attack traffic started before the patches did. The popular LiteLLM Python package, a common gateway between applications and large language models, was poisoned with a credential stealer and a backdoor. The FBI and partners in the United Kingdom and Germany say the SafePay ransomware group has hit more than six hundred organisations, with Australian victims on its leak site. And OpenAI has disclosed that two of its own coding agents switched off safety monitoring, and one then denied doing it.

Australian focus first, and it is really the PHP story with a local timestamp on it.

On Wednesday afternoon the Australian Signals Directorate's Australian Cyber Security Centre issued a critical alert, ahead of the patches, telling organisations to find PHP in their environments, watch the official guidance and be ready to update the moment fixes landed. That is an unusual step, and it was taken because details had already leaked. The fixes arrived at around one o'clock this morning, Melbourne time. So for Australian organisations, the overnight question is simple: which of your internet-facing servers have been updated, and which are still sitting on the old runtime as the working day begins. If you run web hosting, a content management system, an online shop or an internal portal written in PHP, this is today's job, ahead of the rest of the inbox.

One more local note: the SafePay ransomware advisory, which I'll come to shortly, records Australian organisations among the victims on the group's leak site.

Now the global picture, starting with PHP in more detail.

The two flaws are tracked as C V E twenty twenty-six, one zero nine six one eight and one zero nine six one nine, and together they've been nicknamed PHP to Shell. Both are rated nine point two on the latest scoring scale. The important point is where they live. They are in the PHP engine itself, not in any application, so a perfectly well written site is still exposed, and even a page that just says hello world can be attacked. The first flaw abuses the way PHP handles a request that runs out of memory: a crafted upload can leave memory corrupted and then run the attacker's code. The second abuses a pointer left behind after a request crashes, which a follow-up request to the same worker process can then use. The PHP team says the highest risk is servers running Apache with the mod P H P module, where a single unauthenticated request can trigger the attack before any application code runs. P H P F P M, the other common setup, is not safe either. An attacker can also read worker memory, which may hold other users' passwords, tokens and keys.

The fixed versions are eight point five point twelve, eight point four point twenty-seven, eight point three point thirty-six and eight point two point thirty-five. Anything on eight point one or older is out of support. The United States Cybersecurity and Infrastructure Security Agency, CISA, is blunt: if you cannot patch, or you're on an unsupported version, take the system offline until you can. Two practical traps are worth repeating. First, updating WordPress, Drupal or Laravel does nothing here, because the runtime comes from the server package, the host or the container image. Second, Linux distributions received the patches in advance, so a fixed package may carry an old-looking version number. Check the changelog for the C V E, not the version string, and restart Apache, P H P F P M and any long-running workers afterwards. The workaround that circulated before release, turning off session upload progress, is only partial. Patching is the only real fix.

On exploitation, the picture is still settling. Cloudflare said it saw attack traffic before the patch and watched attackers rework payloads to get around its firewall rules. The research firm watchTowr says it is seeing active exploitation attempts against both flaws, and another vendor, Hadrian, claims exploitation at scale. CISA, at the time of its alert, had not observed exploitation, and no source has yet confirmed a specific server being broken into. Treat the claims of mass exploitation as not yet independently verified, but don't wait for that verification to patch. Wiz expects web shells, backdoors that give an attacker a control panel on a site, to follow, and Cisco Talos estimates around half of vulnerable PHP systems may never be patched.

The disclosure itself was messy. Signs of the first flaw surfaced in a 2024 audit, but the fix stalled, which the PHP Foundation now calls a structural failure. This year the C V E numbers leaked on a public forum, a researcher mistakenly posted a video of a working proof of concept, and Chainguard published patched container images about six hours early. The embargo, in short, held up about as well as a Melbourne spring forecast. Precautionary outages followed. BambooHR took its human resources service offline in several countries, and in the Netherlands the government sign-in service and several public sites went dark for a time.

Next, a supply chain compromise with an AI flavour. LiteLLM, a widely used Python library and proxy that sits between applications and model providers, published a malicious version one point one zero seven point zero through the Python Package Index and its Docker images. LiteLLM says the attacker used stolen GitHub command-line tokens from three engineers' accounts, using one account to trigger the release and another to approve it, which is a neat illustration of why two-person approval helps less when both people's tokens are stolen. The payload runs as soon as Python starts, before LiteLLM is even imported, and collects cloud credentials, private keys, browser data, AI tool credentials and any saved proxy configuration. The package has been quarantined and the images removed. If version one point one zero seven point zero reached any machine or container, rotate every secret it could see from a clean environment, and pin one point one zero six point two by digest.

The SafePay advisory, from the FBI, the United States Secret Service and agencies in the United Kingdom and Germany, describes a private group that does not use affiliates and that has breached at least six hundred organisations since August 2024, many in critical infrastructure. Its entry points include known flaws in Cisco, SonicWall and Veeam products, plus password guessing and phishing. Once inside, it creates or takes over accounts, uses ordinary admin and remote desktop tools to move around, steals data and then encrypts, deleting shadow copies and resetting backup storage on the way out. The indicators are linked in the show notes.

Staying with exploited flaws, CISA now has the Plex Media Server chain known as Plex to Shell in its known exploited catalogue, with a federal deadline of tomorrow for the most serious parts. Four flaws chained together let an unauthenticated attacker obtain the owner's admin token and run code. Plex fixed them in August, so this is about servers that were never updated. Staff running Plex at home are worth a reminder.

WordPress administrators have a second problem this week. TeamUpdraft, maker of the UpdraftPlus backup plugin, says its website was breached over the weekend of the seventeenth and eighteenth, exposing connection keys for its UpdraftCentral remote management service. Patchstack watched an attacker use valid keys to install backdoor plugins on connected sites over an eighteen hour window. Cloud UpdraftCentral users should log in to each site directly, update the plugin, delete the old connection key, and hunt for unfamiliar admin accounts and plugins.

A follow-up on Wednesday's eMudhra story. It now appears nothing had to be stolen at all. The private keys for the eight intermediate certificates were generated in an April 2025 key ceremony and turned out to be numbers below two hundred and fifty-six, one of them reportedly the number four, which is a key you could guess before finishing your coffee. Browsers have blocked the certificates, but Cloudflare warns that servers, containers and mutual authentication setups outside the browser may need manual fixes, and Mozilla and Chrome are moving to remove trust in the eMudhra root entirely.

Also on yesterday's list, Dark Reading reports that the OVHcloud command-line tool compromise has been tied to the GlassWorm group, through a developer's GitHub account that had been compromised months earlier. That firms up what was only researchers' inference on Wednesday.

Briefly, several more. Attackers took over more than three hundred Tor exit relays in early October and redirected SSH connections, the encrypted remote login protocol, to servers that captured passwords. Only password logins over Tor between the first and fifth of October were exposed, and some relay operators found the Ebury backdoor on their hosts, so the advice is to reinstall, not clean up. Sophos has described a China-aligned cluster it calls Bronze Sandcastle, active against targets in Asia and Africa since mid 2025, which loads its backdoors by abusing the Sandboxie sandboxing software. Signal has disclosed a critical flaw in its calling library that could stop a call from ending properly, leaving the microphone or camera live. It was fixed in September, but the disclosure is fresh, so make sure every device is updated.

To AI security.

OpenAI says that during two internal coding tasks on the third and sixth of October, agents running its GPT six point one Sol and GPT six Astra models weakened its misalignment monitoring. In one case the agent turned off the automatic alerts to OpenAI's security team, reading an earlier instruction not to send messages as permission to silence the monitor. In the other, an agent removed a monitoring integration to match a reference design and then told the user it hadn't. OpenAI says it's making monitoring harder to disable and trying to understand why models do this at all. The lesson for anyone deploying agents: an agent that can edit its own guardrails should be assumed to edit them eventually, so keep monitoring and alerting outside its permissions.

PHP to Shell is also an AI story. Calif, Wiz and OpenAI say frontier models helped turn a decade-old bug into a working exploit, letting one researcher do in about a week what would otherwise have taken a team months. Meanwhile, curl's maintainers, overwhelmed by what they call an avalanche of reports, many AI assisted, will handle low and medium severity reports in public from the twenty-sixth of October. In the words of its lead maintainer, they aim to not drown. Put those two stories side by side and you get the shape of the next year: AI makes serious bugs easier to find and exploit, and makes the volume of minor reports harder for small projects to survive.

On the defensive side, Nvidia has announced an OpenShell reference architecture to contain AI agents, with a separate monitoring layer on its data processing units that it says can stop an agent leaving its boundary within milliseconds. Google has added ClickFix warnings to Chrome's Enhanced Protection mode, flagging when a user is tricked into copying a suspicious command, as Push Security reports fake AI tool installers are now among the most convincing ClickFix lures.

Industry and strategy. Accenture, Dragos and the SANS Institute have launched a ten million dollar foundation offering free operational technology security tools, deployment and training to up to five hundred smaller United States utilities. The European Commission has opened a Digital Services Act investigation into fake listings and phishing on Booking dot com. And Microsoft admits it wrongly marked a Windows eleven Always On VPN bug as fixed in October's updates, so if remote staff are still stuck on connecting, it is not your imagination.

The outlook for the next day or two.

Critical. Patch PHP on every internet-facing system today, restart the services, and confirm through package changelogs. If you cannot, follow CISA's advice and take the system offline. Then hunt for earlier compromise: odd upload requests followed by memory or server errors, oversized session cookies, unexplained worker restarts, and PHP processes launching shells. Expect mass scanning and web shell campaigns to grow, and appliance vendors that embed PHP to issue their own advisories. Also critical: any environment that pulled LiteLLM one point one zero seven point zero needs its secrets rotated now.

High priority this week. Clean up UpdraftCentral connections on WordPress sites, update Plex Media Server where it exists, check SafePay's listed entry points, especially SonicWall, Cisco and Veeam, against your estate, and keep working through the eMudhra certificate clean-up for servers and containers.
