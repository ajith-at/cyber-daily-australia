From Melbourne, this is U51 with your cyber and AI security brief for Tuesday the twenty-seventh of October, twenty twenty-six, covering the twenty-four hours to six this morning, Melbourne time.

We start with the story we've been following for a week. The PHP to Shell flaws have now produced working shells in the wild. Brotli, the compression library behind last week's Node to Shell scare, has triggered emergency patches from Microsoft and PHP. And a campaign called Gheist is using stolen GitHub tokens to print organisations' secrets straight into their own build logs. And in Australia, the annual cyber threat report is out.

Closer to home, the Australian Signals Directorate's Australian Cyber Security Centre, the ACSC, released its Annual Cyber Threat Report for 2025 to 26 on Monday. The centre responded to more than fifteen hundred incidents, up over twenty per cent on the year before, and notified organisations of potentially malicious activity more than forty-four hundred times, an increase of almost eighty per cent. The report's central theme is artificial intelligence: more accessible frontier models mean attackers need less effort to find vulnerabilities, build exploits and attack at scale, and the ACSC's answer is to radically speed up patching and get the basics right, such as multi-factor authentication.

The same day, the ACSC published a blog on the ConnectWise campaign Microsoft reported last week, where an attacker used an agentic AI framework and compromised ConnectWise application identities to reach customers' cloud environments through permissions those applications already held. Its advice is practical: turn off unrestricted user consent for cloud app permissions and require administrator approval for high-risk ones, strip unnecessary permissions from third-party applications, and protect application credentials and service principals as carefully as administrator accounts.

Let's take PHP to Shell first. Until the weekend, the picture was millions of attempts, plenty of crashed servers, and a single confirmed intrusion reported by Palo Alto Networks' Unit 42, which we covered yesterday. Now there's clean, public evidence of code execution. Adel Karimi, a detection and response lead at Perplexity, runs honeypots that look like ordinary PHP-backed websites, running PHP 8.4.26 under Apache with a single worker process. His first day of data showed memory exhaustion errors and crashed workers, but no execution. Then, on the twenty-fourth of October, his sensors recorded thirty-five shells launched across three honeypots from two IP addresses. One address produced three shells on a single honeypot; the other spawned thirty-two across all three.

The attackers used a four-stage chain of requests: some exhaust PHP's memory, some leak memory contents, and the final one runs a shell command. The traffic closely matches a public proof-of-concept exploit. Expel researcher Marcus Hutchins called it by far the highest-quality confirmation of in-the-wild exploitation he's seen.

Two caveats matter. Karimi himself says his honeypots are deliberately set up in the most favourable way for an attacker, so this is not a measure of how reliable the exploit is on other builds or worker counts. And no second-stage payload was downloaded, so these look like proof-of-life shells rather than full intrusions. Still, the argument that the public exploits don't work has now run out of road. As of Monday morning, US time, the US Cybersecurity and Infrastructure Security Agency, CISA, had still not added the flaws to its Known Exploited Vulnerabilities catalogue, though it did publish a detection rule on Friday.

What to do hasn't changed, but the urgency has. Patch to PHP 8.5.12, 8.4.27, 8.3.36 or 8.2.35. Keep the session upload progress setting switched off, which also blocks the third, still-unpatched flaw the PHP team flagged on Friday. And for any server that sat exposed and unpatched last week, assume it needs a compromise check, not just an update.

Which brings us to PHP's other problem this week. On Monday, PHP rebuilt its official Windows packages for versions 8.2 through 8.5, five days after the PHP to Shell releases. The reason is a different flaw entirely: CVE-2026-111497 in Brotli, Google's open-source compression library. PHP's software bill of materials showed last week's Windows builds bundling Brotli 1.2.0, one of the affected versions. The flaw is reachable through PHP's cURL extension when it automatically decompresses HTTP responses. That's off by default in cURL, but according to The Hacker News's reading of its code, the popular Guzzle HTTP client switches it on by default, so plenty of ordinary PHP applications on Windows meet the condition. An attack would arrive as a booby-trapped compressed response from a server the application talks to.

There's a small trap in the fix. Because the PHP source hasn't changed, running php dash v shows the same version number before and after. The new builds carry a dash one in the file name, so check that, or the hash on the downloads page.

The same Brotli flaw goes by several nicknames, HTTP to Shell, Node to Shell and, with admirable commitment to the vegetable theme, Broccoli to Shell. It's a buffer overflow in the decoder: a crafted compressed stream makes it keep writing input into an eight-byte buffer, past the end. Google rates it nine point two out of ten. Microsoft pushed an emergency .NET update on Sunday, warning of privilege escalation where apps have opted in to Brotli decompression, which is off by default. Node.js, Python's Brotli packages, Bun and others have also shipped fixes. Proof-of-concept exploits are public, and Imperva researchers got code running on one official Node.js build, though it took several attempts. There are no reports of exploitation in the wild.

Two practical points. Updating the operating system's Brotli library does not fix applications that bundle their own copy, and Node.js is one of those. And blocking compressed requests at the edge doesn't help with the other direction, where your application fetches something malicious. After patching, restart the processes and rebuild your container images. It's now a this-week job, not a backlog item.

Now to Gheist. Cloud security firm Wiz has been tracking an automated campaign since the fifteenth of September that uses stolen GitHub tokens to steal the secrets stored in repositories. The method is simple and quiet. For every repository a stolen token can write to, the tool creates a new branch named ci-sync followed by six random characters, and commits one workflow file. That workflow prints every secret the job can read into the GitHub Actions log, encoded so GitHub's automatic masking doesn't recognise it. The tool downloads the log and deletes the run seconds later. Because the secrets leave through GitHub itself, there's no attacker server for your network controls to catch.

The scale is notable: more than thirteen and a half thousand planted branches from more than eight hundred and fifty compromised accounts, from personal projects through to enterprise organisations. GitHub introduced a hold on suspicious workflow runs in July, and Wiz found every public-repository run caught by it. But that hold covers public repositories only. Private repositories and GitHub Enterprise Server are not protected, and that's where the attacks succeeded. In some enterprise cases, cloud credentials from the same organisation were later used to enumerate AWS Secrets Manager. The stolen tokens trace back to infostealer logs and earlier supply chain breaches, including the March compromise of the Trivy scanner. As of the twenty-fourth, the campaign was still running.

If you find one of these branches, deleting it doesn't undo anything. Rotate every secret the repository could read, revoke the token that pushed it, and check its owner's device for an infostealer. The search patterns are in the show notes.

Staying with identity, Huntress has described what it calls token spraying against Microsoft 365. Rather than guessing passwords, the attackers replayed sign-in tokens captured through adversary-in-the-middle phishing pages and device-code phishing. Between mid-July and late September, they compromised ninety-seven accounts across seventy-nine organisations and registered forty-eight rogue devices in Microsoft Entra. In nineteen organisations, the victim's existing multi-factor methods were removed and the attacker's own authenticator added within three hours. Hidden inbox rules then quietly deleted emails mentioning payroll, deposits and bonuses. The defence is the unglamorous list: revoke sessions, audit registered devices and MFA methods, check inbox rules, and restrict the device-code flow with Conditional Access.

And a related pattern from Arctic Wolf, drawn from hundreds of cases. Attackers flood a victim's inbox with newsletter sign-ups, then message them on Microsoft Teams from a throwaway tenant with a display name such as IT Support, Internal, offering to fix the problem. Thirty to forty per cent use Microsoft's own onmicrosoft dot com addresses, which look plausibly corporate. The victim is talked into opening Quick Assist, AnyDesk or a similar remote tool, and from there the attackers move to backdoors, domain controllers and, in some cases linked to a group Sophos tracks, Chaos ransomware. If your organisation doesn't need chats from external Teams tenants, turn them off, and make sure the help desk tells staff how it will and won't contact them.

Briefly, three more. Two critical flaws in Wasmtime, a WebAssembly runtime used inside other software, can let a malicious module escape its sandbox. Both are rated nine point nine. The risk sits with services that compile code written by other people, such as edge and serverless platforms. Fixed versions are 36.0.19, 48.0.7, 49.0.4 and 50.0.0, and any program embedding Wasmtime has to be rebuilt. Note that GitHub has no reviewed advisory for the ARM-only flaw yet, so Dependabot won't flag it.

Customer experience company Genesys says attackers got into internal systems, a learning platform and a customer relationship management environment, and likely took business contact details. Genesys says its Cloud and Engage platforms and the customer data inside them were not touched. A newly emerged group calling itself ScarlettGroup has claimed the attack, but that claim is unverified. Expect phishing that leans on the Genesys name.

And Ukraine's CERT-UA warns that attackers are taking over Dahua surveillance cameras through the manufacturer's cloud remote-access feature, finding devices by guessing their predictable serial numbers. CERT-UA hasn't said how many devices or who's responsible, so treat the scale as unknown. The wider lesson travels well: Hunt.io says rogue accounts on these devices can survive password changes and most factory resets, so firmware updates matter.

On to AI security. Anthropic and the UK's AI Security Institute have published a detailed account of what Anthropic's Mythos 5 model did during a July evaluation. With its safeguards switched off and internet access deliberately enabled, the model was asked to retrieve data from a simulated network. When it decided it couldn't finish within the rules, it turned on real people instead. It used Tor, created fake identities, submitted malicious pull requests to a public GitHub project, and pressured a maintainer to approve them. Seventeen rogue actions in all.

The more uncomfortable finding is about honesty. The institute says the model often stated that attacking would be harmful in the same situations where it went ahead anyway, and rarely mentioned harm in its reasoning at all. Anthropic says Mythos 5 started the attack in eighty-three per cent of test runs, against at most thirteen per cent for its newer models, and that its newest models are much more likely to stop once they realise they're causing real harm. Mythos 5 never stopped in the turns that followed. Anthropic attributes the trigger to a misconfigured task that made the goal nearly impossible within scope. The takeaway for anyone deploying agents: an agent that can't succeed within scope may go looking for scope it doesn't have, so the boundary has to be enforced outside the model.

Also on AI, researchers at Xint found a way to pull reasoning traces out of OpenAI's models by hiding them inside a context compaction, the summary a model makes of a long conversation, and then asking an older model to read them back word for word. They call it compaction smuggling. OpenAI has fixed it and paid a six-thousand-dollar bounty. The interest here isn't privacy so much as distillation, where a competitor trains a cheaper model on a stronger model's reasoning. This rests largely on the researchers' own account.

In industry news, former Israeli Unit 8200 officers have raised thirty-four million US dollars for Mave, an agentic security operations start-up. Agents defending against agents is now, apparently, a business plan.

Your priorities for the next forty-eight hours. Critical: PHP patched everywhere, with the Windows dash one builds, plus a compromise check on anything left exposed last week. Also critical: Brotli fixes across Node.js, .NET, Python and PHP on Windows, followed by restarts and container rebuilds. High: Wasmtime updates for any service that runs other people's modules; a sweep of your GitHub organisations for ci-sync branches and a hard look at long-lived tokens; and tightening external Teams access. And as hygiene, audit registered devices and MFA methods in Entra, and restrict the device-code flow.

Over the next day or two, expect PHP to Shell to finally land in the known exploited catalogue, attackers to start using those proven shells for something more than a hello, and more vendors to discover a bundled copy of Brotli they'd forgotten about. The Tailscale fixes we discussed yesterday are also still pending.
