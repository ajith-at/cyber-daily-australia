Good morning from Melbourne, and welcome to U51, your cyber and AI security brief for Thursday the 12th of November, covering the 24 hours to about six this morning, Melbourne time.

Here are the stories leading today's headlines. Attackers are exploiting two Barracuda flaws that can give them root on email security gateways, and US federal agencies have until Friday to deal with them. Railway says AI keys stolen from its customers in October ran up an estimated 740,000 US dollars in unauthorised usage. The Victorian Curriculum and Assessment Authority's website was hacked in the middle of exam season. And Microsoft researchers showed that editing fewer than ten neurons can plant a backdoor in the model behind an AI agent.

Barracuda says attackers have exploited two vulnerabilities against a small number of organisations. The first is an authorisation bypass in the Email Security Gateway, rated 9.3, that needs no login but does need the device's administrative interface to be reachable. The second is a command injection flaw rated 8.6, which needs administrative access, that affects the gateway plus Barracuda's load balancer, message archiver, web application firewall, its control centre and the web security gateway. Chained together, starting from an exposed admin interface, the two give an attacker root on the device. CISA, the US Cybersecurity and Infrastructure Security Agency, added both to its Known Exploited Vulnerabilities catalogue on Tuesday, flagged them for forensic triage, and gave federal agencies until Friday. Barracuda's advice is to confirm devices are on the latest firmware with every patch applied, to apply patches by hand if automatic patching is off, and to keep administrative interfaces off the internet. The patch identifiers for each product are in the show notes. Anyone whose admin page was reachable from the internet should check for compromise as well as patch.

Australian focus.

The Victorian Curriculum and Assessment Authority, the VCAA, confirmed its website was hacked yesterday, while the state's exams are still running until the 18th of November. A message posted on the defaced site, signed by someone calling themselves DaggerElite, claimed the 2026 exam papers had been taken from a printing provider's file servers and that they had sold them to students. The attacker also claimed to have taken email details from a legal services provider. The VCAA says it is running a forensic investigation and that there is no indication exam papers have been accessed. The claims about the printer, the papers and the sale come only from the attacker and are unverified.

Parks Victoria has suspended new campsite bookings after a broader data breach at Bookeasy, its external booking provider, and reports of suspicious WhatsApp messages sent to customers about their bookings. Existing bookings stand. Parks Victoria says it never contacts customers on WhatsApp, so any such message asking for payment or personal details should be ignored. The scale of the Bookeasy breach and which other operators use it have not been disclosed.

Global threats.

A short update on N-able. After taking hosted N-central offline on Monday, N-able released a hotfix on Tuesday, US time, covering seven CVEs, including XML external entity, injection and path traversal flaws that reach code execution, plus a route to root. Hosted servers have been upgraded. On-premises customers should keep their servers offline until upgraded, then upgrade agents before probes, because an upgraded probe can't talk to older agents. Built-in remote control is disabled for now, and a second hotfix is planned for the rest of the published flaws. The build number is in the show notes. N-able still reports only scanning tied to the public exploits, not confirmed customer compromise, but patching tells you nothing about what happened while a server was exposed, so check logs from the weekend onward.

CISA also added two older bugs to its catalogue. One is an XML external entity flaw in Cisco BroadWorks, the calling platform many telcos run, which lets an unauthenticated attacker read configuration files and was fixed in August. The other is in Openwave's Webtop media transcoder, a webmail component, where an authenticated user can upload a crafted file to obtain sensitive information; Japan's vulnerability notes service published the fix on Monday, and the developer says attacks have been seen. Both are now confirmed exploited, so those earlier fixes have become urgent.

Zoom has fixed a critical flaw in Zoom Workplace for Windows, rated 9.6, that could let an unauthenticated attacker escalate privileges over the network, though a user has to take some action for it to work, along with a second flaw rated 8.1. Neither is reported as exploited. Update to the fixed version listed in the show notes.

Git has fixed a flaw that lets a malicious repository run code on a machine that clones it with the recurse submodules option. An over-long path slips past Git's safety check and is then written to disk under a shorter name that can be made to point at attacker-controlled hooks. Such a repository is hard to push to the big hosting sites, but an innocent-looking project that simply points to it as a submodule is enough. Fixes cover every supported series; the versions are in the show notes. Git for Windows had not shipped a matching release as of Tuesday, so Windows build agents may need to wait. Build servers and developer machines that clone untrusted repositories recursively are the priority.

The Indian certificate authority eMudhra has revoked eight more intermediate certificate authorities, after earlier saying they were unaffected by its October key compromise. Their keys were not shown to be weak, but the same internal script had pulled them from the hardware security modules, and eMudhra says it cannot show they were handled under its own rules. Six issued website certificates. Expect affected certificates to need replacing.

AI security.

Railway, the app hosting platform, published its full report on an October breach. The attacker used an unknown flaw in Railway's build system to steal a build credential, which an internal workflow service trusted far beyond its purpose. From there the attacker read build histories and a copy of the source code, found a misconfigured identity binding in the deployment pipeline, and reached a credential that could decrypt customer environment variables in at most about 100,000 workspaces, or 1.85 percent. Database queries targeted variables named like AI provider keys. Railway estimates 740,000 US dollars of unauthorised AI usage, and says it will cover charges that providers decline to refund, reversing its October position. Railway also links this to similar key thefts at other AI platforms through October. If you stored AI keys on Railway, rotate them and set spending limits with each provider.

Microsoft Research has shown a technique it calls Lazarus, which plants a backdoor in a language model by editing fewer than ten neurons that rarely fire, with no retraining. When a chosen trigger appears in the agent's context, such as a date in a terminal, the model emits a command of the attacker's choosing, and the agent runs it with whatever access it has. In recorded tests using a harmless test command, seven edited neurons in one eight-billion-parameter model produced it on almost every triggered run and never on clean ones; in free-running tests one setup produced it in a tiny fraction of untriggered sessions. Those rates measure the model emitting the command, not a completed attack. It needs write access to the model's weights, and Microsoft has told The Hacker News it has seen no one use it. Microsoft's advice is to check where model weights came from, compare them against the original, and watch for changes after deployment.

Arctic Wolf has linked AntiFox, an open-source AI-driven penetration testing platform, to real intrusions run from servers on Alibaba Cloud. One pattern went from web shells on Microsoft IIS servers to reading credentials in configuration files, then to automated sweeps across dozens of AWS services; other cases began with valid AWS credentials obtained by unknown means, and one involved reading, copying and deleting stored files. In one case the tool cycled through several identities, sent hundreds of requests in about half an hour, and among mostly access-denied errors managed to read a production secret. A burst of failed API calls can hide one that worked, so check the successes in the logs too.

Researchers at Claroc checked about 37,500 Grok app addresses they found online and say 35,578 of them could be opened by anyone with the link, the sharing option that was preselected in the account they tested. About one in ten held business or personal data, including an intensive care patient briefing and a timesheet with plain-text passwords, and 24 belonged to staff of SpaceXSI, Grok's maker, and X. SpaceXSI took down its staff apps, but not those of other users. Anyone whose team builds apps this way should review sharing settings now.

NEAR AI disclosed on the 9th of November that an attacker exploited a remote code execution flaw in SGLang, an open-source inference engine, to run code on one of its inference servers. Because SGLang runs inside its trusted execution environment, on the 8th of November the attacker could have seen requests processed on that server, including ones sent in confidential mode. A trusted execution environment protects against the host, not against a bug in the software inside it. The attacker took account details for about 100 users and data from 18 legacy agents, and two cloud customers' API keys were exposed in logs and have been revoked. These figures are the company's own.

Outlook and patch priorities.

First, Barracuda gateways and appliances: patch, take admin interfaces off the internet and check for signs of compromise, today. Second, N-able N-central on-premises: apply the hotfix before reconnecting, and review activity since the weekend. Third, Cisco BroadWorks and Openwave patches from earlier this year, now that both are confirmed exploited. Then Zoom Workplace for Windows and Git, especially on build systems. On the AI side, rotate any AI provider keys held by hosting platforms and set spend caps, and audit where your model weights come from. Locally, expect more detail from the VCAA investigation and from Bookeasy on who else is affected, and treat unexpected booking messages as phishing.
